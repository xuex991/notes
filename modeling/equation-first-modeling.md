# 轻量等式建模

轻量等式建模（Lightweight Equation-First Modeling）是一种概念建模方法：先用简单等式定义事物由什么组成、如何流动，再讨论数据结构和代码实现。

它不追求数学上的完全精确，而追求**最小充分精度**：模型只需要精确到足以支持当前讨论和下一步决策。

## 核心思想

```text
复杂概念 = 简单概念 + 简单概念
```

通过逐层展开等式，让模型中的名称、职责和边界变得清楚。

```text
Job = Config + Worker
Config = Context + Trigger + Policy
Context = Input + Output
Worker(Context) → Result
```

## 基本符号

```text
=   定义
+   组成
→   输入、输出或流向
1:1 / 1:N   数量关系
```

符号只表达一种固定含义。出现歧义时，应补充一句自然语言定义，而不是增加更多符号。

## 建模步骤

1. 用一个等式写出核心概念。
2. 继续展开其中不清楚的部分。
3. 为每个名称写一句职责说明。
4. 检查概念之间是否重复或互相越界。
5. 当模型足以支持下一步决策时停止。

例如：

```text
Job = Config + Worker
```

- **Job**：一个可以被执行的完整单元。
- **Config**：描述执行需要的上下文、触发方式和策略。
- **Worker**：读取 Context 并产生 Result 的执行逻辑。

继续展开：

```text
Config = Context + Trigger + Policy
```

- **Context**：处理什么，以及结果去哪里。
- **Trigger**：什么时候执行。
- **Policy**：以什么限制和规则执行，例如超时、重试和并发。

## 使用原则

### 先定义名称

先确认概念叫什么、负责什么，再设计类、字段、数据库表和 API。

### 逐层展开

不要一次描述整个系统。只展开当前有歧义或需要决策的部分。

### 保持单一职责

等式右侧的每个概念应有独立职责。两个概念无法清楚区分时，应合并或重新命名。

### 使用最小充分精度

模型不是越精确越好。额外精度会引入额外概念、规则和维护成本。只保留当前阶段真正影响决策的细节。

## 适用范围

轻量等式建模适合：

- 定义产品和领域概念
- 讨论模块职责和边界
- 寻找简洁、稳定的命名
- 在业务人员和工程师之间建立共同理解
- 在实现前快速比较不同方案

它不适合独立描述：

- 完整的数据约束和数量关系
- 生命周期和复杂状态变化
- 并发、事务和一致性
- 权限、安全和异常恢复
- 具体 API、数据库或部署实现

这些内容出现后，应继续使用关系图、状态机、Schema、接口和测试补充，而不是把等式变成复杂的形式化语言。

## 方法边界

轻量等式建模是概念模型的第一层，不是最终技术规格。

```text
等式模型 → 关系与数量 → 状态与规则 → 接口与实现
```

它的价值不是完整描述系统，而是用尽可能少的概念，让所有人先对“我们正在构建什么”达成一致。
